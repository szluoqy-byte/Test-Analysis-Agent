# 测试点生成 Skill

本 skill 在需求结构化、方法路由和专项分析之后使用。

## 输入

- 结构化需求模型。
- `testing-method-router` 输出的方法路由表。
- `ME-*` 方法分析证据摘要。
- 风险分析结果。
- 边界/等价类、状态、决策表、场景流、权限、接口、数据一致性、组合兼容等分析结果。
- `knowledge/testpoint-standard.md`。
- `knowledge/test-oracle-heuristics.md`。
- `templates/testpoint-output-template.md`。

## 生成步骤

1. 按需求模块分组。
2. 生成中等粒度测试点。
3. 将 `测试点` 写成“验证被测对象在特定场景下的某一功能/规则/行为是否符合需求”的无歧义句子。
4. 从标准分类中选择 `类型`。
5. 从方法路由和方法证据中填写 `方法`。
6. 填写需求依据或标记为“风险确认点”。
7. 根据风险规则分配级别，级别取值以 `knowledge/testpoint-standard.md` 为准。
8. 填写简短风险说明、判定依据、不确定性或关联证据 ID。
9. 去重，并合并过细测试点。
10. 将同一份测试点明细提供给完整报告和独立明细文件复用，避免两个产物内容不一致。

## 标准来源

- `类型`、`方法`、`级别`、粒度和非用例化约束以 `knowledge/testpoint-standard.md` 为准。
- 判定依据启发以 `knowledge/test-oracle-heuristics.md` 为准。

## 约束

- 不写前置条件、操作步骤、具体测试数据或完整预期结果。
- 不使用 `前置条件`、`操作步骤`、`测试数据`、`预期结果` 作为列名。
- 每条测试点是对验证特性的细化，必须明确被测对象、特定场景和某一功能/规则/行为。
- 每个 `必选` 方法必须产出至少一个测试点或一个待确认问题。
- 每个测试点应能追溯到一个需求依据和一个方法证据；不在测试点表中新增证据列。
- 缺少判定依据时，不隐藏问题，标记为“待确认”。
- 本阶段原则上不触发交互澄清；如发现缺口，写入待确认问题或风险确认点。
