# 测试方法路由 Skill

本 skill 用来决定“该用什么测试方法分析这段需求”。它是防止 Agent 泛泛生成测试点的关键环节。

## 输入

- 结构化需求模型。
- 记忆上下文包。
- `knowledge/test-method-routing-matrix.md`。
- `knowledge/coverage-taxonomy.md`。

## 分析步骤

1. 逐条扫描需求片段，识别触发信号。
2. 将触发信号映射到一个或多个测试方法。
3. 将方法标记为 `必选`、`可选` 或 `不适用`。
4. 根据需求明确程度标记置信度：`高`、`中`、`低`。
5. 说明选择或跳过某个方法的原因。
6. 将方法路由结果传递给测试点生成阶段。

## 输出

| 需求片段 | 触发信号 | 适用方法 | 调用 skill | 必要性 | 置信度 | 说明 |
|---|---|---|---|---|---|---|

## 路由规则

- 路由矩阵以 `knowledge/test-method-routing-matrix.md` 为准。
- 覆盖要求以 `knowledge/coverage-taxonomy.md` 为准。
- 本 skill 只负责把当前需求片段映射到方法，并说明选择或跳过原因。

## 约束

- 跳过某个明显相关的方法时，必须给出原因。
- 被标记为 `必选` 的方法，最终必须生成测试点或待确认问题。
