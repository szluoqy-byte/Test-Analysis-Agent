# 业务域 Memory：测试分析 Agent

本文件保存 Test Analysis Agent 项目自身已经确认的业务域上下文。

## 适用范围

- Markdown 需求文档分析。
- 测试点分析报告生成。
- 测试方法路由和方法证据汇总。
- Memory 上下文构建和质量门禁审查。

## 关键词

- 需求文档
- 测试点
- 测试方法路由
- 方法证据
- 质量门禁
- Memory
- 记忆上下文包

## 领域术语

| 术语 | 含义 | 来源 | 备注 |
|---|---|---|---|
| 需求文档 | 输入给 Agent 的 Markdown 产品或业务需求说明 | 项目设计 | v1 只支持单文件 |
| 测试点 | 需要验证的目标或风险，不包含步骤和具体数据 | 用户确认 | 不是测试用例 |
| 需求依据 | 测试点对应的需求标题、段落、表格行或规则摘要 | 项目设计 | 用于可追踪性 |
| 方法证据 | 专项测试方法分析后的 `ME-*` 证据摘要 | 项目设计 | 用于证明测试理论被实际应用 |
| 记忆上下文包 | 每次分析前从 memory 组装的上下文摘要 | 项目设计 | 避免全量注入 |

暂无经确认的项目角色和权限差异。

## 业务设计约束

- 主流程面向单个 Markdown 需求文档。
- 输出是测试点分析报告，不是测试用例、测试步骤或自动化脚本。
- 测试点必须体现被测对象、特定场景和验证特性。
- 方法路由、方法证据、测试点生成和覆盖审查需要形成可追踪链路。
- Memory 只保存经确认的项目事实和项目经验，不保存未确认假设。

## 接口和数据约定

- 每次运行创建独立目录 `outputs/runs/<run-id>/`。
- 完整报告输出到 `outputs/runs/<run-id>/<需求文件名安全短名>.test-points.md`。
- 独立测试点明细输出到 `outputs/runs/<run-id>/<需求文件名安全短名>.testpoint-details.md`。
- 澄清会话输出到 `outputs/runs/<run-id>/clarification-session.md`。
- 本次运行上下文快照输出到 `outputs/runs/<run-id>/context-pack.md`。
- `context-pack.md` 是单次运行产物，跟随 `run-id` 保存，不作为全局 memory 文件。

## 输出偏好补充

- 完整报告必须包含测试方法路由、方法证据摘要、质量门禁结果、专家评分和建议沉淀的 Memory 更新。
- 独立测试点明细只保留测试点明细表和必要元信息，不包含质量门禁、专家评分或 memory 更新建议。

## 非范围

- 不生成测试用例。
- 不生成测试执行步骤。
- 不生成自动化脚本。
- 不把单次运行的完整中间产物沉淀为长期 memory。
