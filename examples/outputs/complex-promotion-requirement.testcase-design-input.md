# 示例需求：限时优惠与订单支付 测试用例设计输入

## 1. 需求信息

| 字段 | 内容 |
|---|---|
| 需求 ID | REQ-SAMPLE-PROMOTION-PAY-001 |
| 需求名称 | 限时优惠与订单支付 |
| 需求描述 | 平台在大促期间支持限时优惠券。用户下单时可以使用一张优惠券抵扣订单金额，支付成功后需要锁定优惠券使用状态并扣减库存；系统需覆盖领取限制、适用商品、金额门槛、会员折扣、支付状态、接口回调、兼容和日志。 |
| 本次不覆盖内容 | 不覆盖优惠券活动后台配置页面细节、退款到账、支付渠道内部清算、真实生产压测、安全渗透、自动化脚本和运营活动数据生产。 |

## 3. 测试场景详情

### SC-001 用户领取限时优惠券

#### 场景测试条件

##### 必填条件

| 条件项 | 内容 |
|---|---|
| 场景入口/触发方式 | 用户在大促活动页、优惠券领取入口或领券组件触发优惠券领取 |
| 执行用户/角色 | 普通用户 |
| 前置条件 | 用户已登录；优惠券活动已配置开始时间、结束时间、库存和单用户领取限制；优惠券库存和领取记录可按用例准备 |
| 测试数据因子 | 活动时间：开始前/活动期内/结束后；优惠券库存：大于 0/等于 0；用户领取次数：0 次/1 次/超过限制 |
| 业务设计约束 | 优惠券活动有开始时间和结束时间；库存为 0 时用户不能领取；每个用户同一活动最多领取 1 张优惠券 |

| TP-002 | 优惠券库存为 0 时用户不应领取成功 | 功能性 | 功能正确性测试 | Level 0 | 防止超发 |
| TP-003 | 同一用户在同一活动中最多只能领取 1 张优惠券 | 功能性 | 功能正确性测试 | Level 0 | 防止重复领取 |
