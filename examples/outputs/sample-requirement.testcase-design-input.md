# 示例需求：订单取消 测试用例设计输入

## 1. 需求信息

| 字段 | 内容 |
|---|---|
| 需求 ID | REQ-SAMPLE-ORDER-CANCEL-001 |
| 需求名称 | 订单取消 |
| 需求描述 | 用户在订单未完成前可以取消订单。取消后订单不可继续支付，系统需要释放库存并记录取消原因；普通用户只能取消自己的订单，客服可以帮助用户取消订单。 |
| 本次不覆盖内容 | 不覆盖发货后物流拦截、退款到账、库存服务内部实现、客服审核通过或拒绝后的完整状态规则、自动化脚本和生产环境压测。 |

## 2. 测试场景清单

| 场景 ID | 场景名称 | 场景测试类型 | 场景目标 |
|---|---|---|---|
| SC-001 | 普通用户取消待支付订单 | 功能正确性测试 | 验证普通用户在自己的待支付订单场景下可以完成取消，取消后订单不可继续支付 |
| SC-002 | 用户取消不可取消订单和重复取消请求 | 容错容灾测试 | 验证已发货订单、重复取消请求等限制或异常条件下，系统保持规则正确且不会重复释放库存 |
| SC-003 | 客服协助用户取消订单 | 功能交互测试 | 验证客服协助取消订单时的角色权限和已支付未发货订单取消申请规则 |
| SC-004 | 订单取消成功后的数据和日志记录 | 功能正确性测试 | 验证取消成功后库存释放和操作日志记录满足需求，并支撑审计追踪 |

## 3. 测试场景详情

### SC-001 普通用户取消待支付订单

#### 场景测试条件

##### 必填条件

| 条件项 | 内容 |
|---|---|
| 场景入口/触发方式 | 普通用户进入自己的订单详情或订单列表后触发订单取消能力 |
| 执行用户/角色 | 普通用户 |
| 前置条件 | 普通用户已登录；订单归属于当前用户；订单处于待支付状态；订单取消服务和库存服务可用 |
| 测试数据因子 | 订单归属：本人订单/非本人订单；订单状态：待支付；库存释放对象：订单关联商品库存；取消原因：用户选择或填写的取消原因 |
| 业务设计约束 | 待支付订单允许取消；取消成功后订单不可继续支付；普通用户只能取消自己的订单 |

#### 测试点

| 测试点 ID | 测试点 | 大类 | 子类 | 级别 | 风险/备注 |
|---|---|---|---|---|---|
| TP-001 | 待支付订单应允许归属用户取消且取消结果符合规则 | 功能性 | 功能正确性测试 | Level 0 | 核心状态流转 |
| TP-002 | 普通用户只能取消自己的订单 | 功能性 | 功能正确性测试 | Level 0 | 防止越权操作 |

| 前置条件 | 用户已登录；系统存在待支付订单、已发货订单和已取消订单；库存释放结果可观察 |
