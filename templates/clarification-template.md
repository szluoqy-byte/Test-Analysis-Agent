# 澄清问题模板

澄清闸门生成交互问题和澄清会话产物时使用以下结构。

## AskUserQuestion 问题结构

每个问题应能映射到 Claude Code 的 `AskUserQuestion`：

```json
{
  "questions": [
    {
      "header": "优惠叠加",
      "question": "会员折扣和优惠券是否允许同时叠加？",
      "options": [
        {
          "label": "按活动配置",
          "description": "测试点需要覆盖配置开启、关闭及规则变更"
        },
        {
          "label": "允许叠加",
          "description": "两类优惠可以同时生效"
        },
        {
          "label": "不允许叠加",
          "description": "两类优惠互斥，只能生效一种"
        },
        {
          "label": "暂不确认",
          "description": "作为待确认风险点继续，不沉淀为业务规则"
        }
      ],
      "multiSelect": false
    }
  ]
}
```

宿主 UI 应保留自定义回答入口；自定义回答按用户原文写入澄清会话产物。

## 澄清会话产物

```markdown
# <需求名称> 澄清会话

## 基本信息

- 需求文档：
- 生成时间：
- 当前状态：Pending / Answered / ContinuedWithRisk

## 问题队列

| 问题ID | 标题 | 问题 | 阻塞级别 | 状态 | 关联需求依据 |
|---|---|---|---|---|---|

## 用户回答

| 问题ID | 用户回答 | 回答类型 | 是否进入本次上下文 | 是否建议沉淀 memory |
|---|---|---|---|---|

## 本次上下文补充

## 继续分析时保留的待确认风险
```

## 问题设计要求

- 一次最多提出 1 到 4 个问题。
- 问题必须说明会影响哪些测试分析结论。
- 选项描述要体现取舍，不写空泛描述。
- 至少包含一个“不确认也可继续”的保守选项。
- 用户自定义回答必须逐字保留，不自动泛化为长期事实。
