# 质量门禁：测试方法应用检查

## 目的

确保 Agent 真正应用了相关测试理论，而不是生成泛化测试点。

## 必需输入

- 测试方法路由表。
- 方法分析证据摘要。
- 测试用例设计输入。
- 如有过程报告，读取其中的设计输入映射。
- 结构化需求模型。

## 失败条件

- 过程报告没有测试方法路由表。
- 过程报告没有方法分析证据摘要。
- 标记为 `必选` 的方法没有映射到场景测试点/接口测试点且没有待确认问题。
- 标记为 `必选` 的方法没有方法证据且没有待确认问题解释。
- 过程报告的设计输入映射缺少方法证据关联。
- 需求信号明显需要某方法，但被跳过且没有解释。
- 过程报告中的方法证据与设计输入中的测试点明显冲突。

## 警告条件

- 大多数行只使用泛化功能分析。
- 高风险方法被标记为可选但没有理由。

## 通过条件

- 每个选中方法都出现在路由表中。
- 每个选中方法都体现在方法证据、设计输入测试点或待确认问题中。
